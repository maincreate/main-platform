Set up the GitHub connection

To connect, Main{Create} needs a dedicated GitHub App with Device Flow enabled. You can configure its public Client ID here once; no access token, password or private key is needed.

Don't have a GitHub App? Register one on GitHub under your chosen owner or organization. Enable Device Flow in the App's settings. Grant only the permissions your chosen features require, such as Repository creation: write when enabled.

A deployment integration's GitHub App is a different concern and should remain separate.

Self-hosted runner policy

Main{Create} is designed to use your self-hosted builders. Before continuing, disable GitHub's standard hosted runners for this organization. This is a GitHub organization setting, not the self-hosted runner permission switch.

Open organization Actions settings ↗ and under Standard hosted runners, select Disable for all repositories, then save.

This confirmation is recorded in Main{Create}, not verified by the GitHub API.

Disabling standard hosted runners is supported on GitHub Team and Enterprise. It blocks ordinary hosted runner labels; hosted runner groups may still be allowed. For strictly self-hosted execution, also restrict runner groups and workflow targets.

To select an organization, first install this GitHub App on that organization in GitHub. Then return and choose Refresh organizations. Create an organization if you don't have one. Selecting an organization does not install or grant runners access.
